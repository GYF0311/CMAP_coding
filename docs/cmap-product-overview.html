CMAP

Project Memory Map

CMAP 是给 AI coding 项目使用的 repo-local 项目记忆地图。它把项目目标、模块职责、当前主线、历史决策、验证方式和候选变更收进仓库里的 `.context/`，让人类、Codex 和 Claude Code 在同一张项目地图上协作。

一句话

它不是 AI coding 全家桶，而是项目持续可理解的底座。

CMAP 的核心产品判断很克制：AI 负责理解、总结、提出候选；CLI 负责固定格式、路径安全、校验、证据收集、候选治理；人类负责最后的语义确认。

Project Evolution

CMAP 的引进过程：从项目小地图，到人类审阅层。

这个项目不是一开始就想做复杂平台，而是在真实 AI coding dogfood 中一点点收窄边界：先解决续接，再解决可发现性，再解决 AI 能写什么、不能写什么。

先落地 `init`、`verify`、`install`、`route`、`checkpoint` 等基础命令，让项目拥有第一张 `.context` 小地图。

Design Thinking

引进 CMAP 的思路，是把“项目记忆”拆成三层。

这三层是 CMAP 的产品边界，也是它和普通文档、普通 AI 总结工具最大的区别。

1

Canonical Facts

`.context/MAP.md`、`STATUS.md`、`CHECKPOINT.md`、`DECISIONS.md` 和 `modules/*.md` 才是项目正式事实。它们描述项目当前是什么，而不是某一次模型怎么想。

2

Generated Support

`generated/`、evidence、stats、freshness 这类内容只做支持材料。它们可以提醒你“哪里可能变了”，但不能替代人类审阅过的模块职责和决策。

3

Candidate Inbox

AI、外部 workflow 或 review 工具提出的语义更新先进 `inbox/`。低风险候选可以按规则提升，高风险语义必须由人看过再进正式地图。

CMAP 最重要的一句话：AI 写语义候选，CLI 做确定性维护，人类决定什么成为项目事实。

Modules

每个模块负责什么：从路由、开工包到审阅台。

下面不是代码目录列表，而是 CMAP 这张项目地图里的产品能力拆分。每个模块都有自己的 `.context/modules/*.md`，AI 修改前应该先读对应模块文档。

cli

入口

负责命令注册、参数解析和退出码边界，是所有 `cmap` 命令的总入口。

context

骨架

生成 `.context` 模板、读取 policy、扫描项目确定性信号，帮助新项目建立地图。

verify

校验

检查 `.context` 结构、占位符、stale/freshness 和 CI 报告，避免地图悄悄漂移。

host

接入

生成 `AGENTS.md` 与 `CLAUDE.md`，让 Codex 或 Claude Code 知道先读哪里、怎么路由。

route

定位

根据任务描述推荐直接相关模块、上下文模块和验证命令，是 AI 开工前的第一步。

graph

关系

从已审阅模块文档生成确定性模块关系投影，不做 import graph，不猜测代码语义。

brief

开工包

把 route、checkpoint、status、模块文档和验证提醒打包成 AI coding startup brief。

pack

上下文

按 token 预算生成脱敏上下文包，只取路由邻域，不把整个仓库无边界塞给 AI。

benchmark

评测

用 JSONL 任务集评估 route 的 Top-1、Top-3 和上下文命中率，并可作为 CI 阈值。

handoff

续接

维护 `CHECKPOINT.md` 和 `STATUS.md`，解决新会话、上下文压缩后的接手问题。

cp

搬运

做安全行块 copy/move/delete/restore，并带备份，降低手动改 Markdown 的误伤风险。

finish

收尾

任务结束时生成 QA-lite closeout，提醒哪些 context 需要更新，也能生成 MapPatch 请求。

update-agent

闸门

处理 AI 写的 MapPatch，routine/generated 可按策略应用，语义更新进入 inbox。

evidence

证据

记录 generated evidence、stats、freshness 与 inbox backlog，帮助人看见支持材料。

view

审阅台

导出只读 HTML review dashboard，展示地图、证据、freshness 和候选，不写项目状态。

relation-candidates

关系候选

接收 AI RelationPatch，校验后写入候选池，v0.2 不自动提升为 canonical 关系。

obsidian-adapter

视图

把 `.context` 导出为 Obsidian 友好的 Markdown，供阅读和图谱查看，但不是事实源。

reconcile-adapter

对账

读取 GSD 等外部 workflow 产物，生成 dry-run 候选或 inbox 项，而不是直接改地图。

showcase

展示

维护当前这个产品介绍 HTML，用于人类理解、外部评审和项目介绍。

memory-lite

轻记录

提供 `log` 与 `idea`，用于显式记录工作日志和灵感，但不把它们当正式事实。

adoption

接管

帮助已有项目生成 adoption workspace 和候选模块信号，先分析，再决定怎么纳入地图。

module-docs

模块文档

创建候选模块文档，不自动改 MAP，让模块扩展保持可审阅。

hooks-doctor

诊断

提供 hook 模板、Codex lifecycle render/ingest、assist/strict 模式和 doctor 检查。

tests

验证

用 Vitest integration tests 和 smoke test 覆盖 CLI 行为，确保产品承诺能落到命令。

Workflow

怎么用：先建地图，再让 AI 带着地图工作。

CMAP 的日常使用不追求复杂，而是让每次 AI coding 都有稳定开工入口、明确模块边界和可验证收尾。

1

初始化或接管

新项目用 `cmap init --auto`，已有项目用 `cmap adopt`，先建立 `.context` 骨架。

2

安装宿主入口

运行 `cmap install --host both`，生成 AGENTS/CLAUDE，让 AI 知道先读地图。

3

开工前路由

用 `cmap route "任务"` 找模块，再用 `brief` 或 `pack` 生成受控上下文。

4

AI 在边界内修改

AI 可以改代码、提出 MapPatch 或 RelationPatch，但语义候选先进 inbox。

5

人类审阅候选

通过 `inbox triage`、`view export` 看证据、freshness 和候选，决定 promote/reject。

6

验证并收尾

运行 `verify`、`finish`、测试和 CI，必要时更新 checkpoint，给下一次会话续接。

新项目 Quick Start

cmap init --auto
cmap install --host both
cmap verify

已有项目接入

cmap adopt
cmap install --host both
cmap route "你要做的任务"
cmap brief "你要做的任务" --max-context 4

Install

安装到本机，再给 Codex 或 Claude Code 一个清晰入口。

正式 npm 包是 @xiaowuovo/cmapcoding，安装后的命令仍是 cmap。也可以从 GitHub 源码构建安装。

C

Codex 接入

先把 `cmap` 安装成本机命令，再进入你的业务仓库执行 Codex host 安装。它会生成 `AGENTS.md`，提醒 Codex 先读 `.context/MAP.md`、`CHECKPOINT.md` 和相关模块文档。

npm install -g @xiaowuovo/cmapcoding

cd /path/to/your-project
cmap init --auto
cmap install --host codex
cmap verify
AI

Claude Code 接入

Claude Code 侧入口是 `CLAUDE.md`。如果你口头说 Cloud Code，这里对应的是 Claude Code 这个 AI coding 宿主；CMAP 仍然保持 host-neutral，只写项目本地入口。

npm install -g @xiaowuovo/cmapcoding

cd /path/to/your-project
cmap adopt
cmap install --host claude
cmap verify

Codex 显式工作流

不依赖 hook parity 时，可以用 `cmap codex start/finish/guard/handoff` 走显式流程。这样更稳，也更容易在 PR 和 CI 里复核。

cmap codex start "修复登录页表单校验" --write-brief --write-pack
cmap codex guard --changed
cmap codex finish --task "修复登录页表单校验" --verified "pnpm test"

可选 hooks 辅助

hooks 是辅助层，不应该直接写 canonical facts。推荐先用 observe/assist，看噪音是否可控，再决定是否启用 strict。

cmap install --host both --hooks assist
cmap hooks render --host codex --mode assist
cmap hooks test --event UserPromptSubmit --mode assist --prompt "更新产品页"
