cmap verify

工作流闭环

从自然语言任务开始，到模块路由、handoff、AI brief、实现、收工、验证、Obsidian 视图更新，形成一个可重复的 AI coding 操作链。

01 / route

任务定位

根据 alias、模块名、路径关键词和模块索引推荐 top modules。

02 / checkpoint

保存 handoff

记录当前任务、假设、已改文件、验证结果、下一步和不要重复做的事。

03 / brief

打包开工上下文

把 route、checkpoint、module docs 和验证规则打成 AI 可读的开工包。

04 / implement

小范围修改

AI 只读相关模块，按证据扩展影响范围，避免盲改全仓。

05 / finish

收工 gate

列 changed files、affected modules、context 更新建议和 checkpoint close/write 提醒。

06 / verify

漂移校验

检查必需文件、frontmatter、关系、路径、changed-file coverage。

07 / view

导出图谱视图

把 `.context` 渲染为 Obsidian-friendly Markdown，供阅读和 Graph 使用。

模块目录

这些模块不是文件清单，而是 AI 开工前应该理解的职责边界。点击上方 mind map 节点或搜索模块名，可快速定位。

当前 dogfood 状态

这个仓库正在用自己维护自己。最近一轮更新把 `finish` 和 `CHECKPOINT.md` 连接起来，避免“做完了代码，但 handoff 状态没有收口”。

实践链路

$ cmap route "补齐收工 checkpoint 闭环"
Likely modules:
1. finish
2. handoff
3. tests

$ cmap checkpoint write --task "Close finish/checkpoint handoff loop" --next "Run full verification"
Updated .context/CHECKPOINT.md

$ cmap finish --changed src/commands/finish.ts,tests/integration/m3.test.ts
Context Updates Needed:
- STATUS.md
- CHECKPOINT.md
- .context/modules/finish.md

Handoff Actions:
- cmap checkpoint write --task "current task" --next "next step"
- cmap checkpoint close

$ pnpm test && pnpm smoke
36 tests passed / smoke passed

可行性判断

  • 可续接`CHECKPOINT.md` 已经成为 brief 和收工流程的一等输入。
  • 可验证`verify --coverage` 能检查 changed files 是否映射到模块。
  • 可阅读Obsidian export 把模块导成带 Properties 和 wikilinks 的 notes。
  • 可扩展`reconcile` 只写 inbox 候选，给 GSD/gstack/superpowers 留了安全入口。
  • 可控边界CLI 做确定性动作，AI/人负责语义判断和长期事实确认。

Obsidian 视图层

`.context` 继续做事实源，`_cmap/CMAP_coding` 只是阅读和关系图谱层。这样既能看图谱，又不会形成双事实源。

Export

`cmap obsidian export` 生成 `00_INDEX.md` 和 `modules/*.md`，正文 wikilinks 让 Graph 形成边。

Open

`cmap obsidian open ` 打印 `obsidian://open` URI，用终端跳转模块说明。

Pull dry-run

Obsidian 人工补充内容后，只生成候选 diff 或 inbox，不直接改 `.context`。

Graph

在 Obsidian 中用 `path:_cmap/CMAP_coding` 过滤，查看孤立模块、高风险模块和依赖聚类。
