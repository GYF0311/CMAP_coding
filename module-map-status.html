模块相关性读法

用户命令 → cli → command modules `cli` 负责命令注册和退出码，具体行为交给 `route`、`verify`、`cp` 等模块。
context → MAP / modules / VERIFY `context` 创建结构；AI / 用户写语义；`verify` 检查结构是否仍可信。
adoption / module-docs → candidate 接管已有项目和新增模块时，只生成候选，不直接升级为可信项目事实。
host / hooks-doctor → reminders only 宿主入口和 hook 负责提醒 AI 维护地图，不越界自动改 `MAP.md` / `STATUS.md`。

    为什么不是每个文件一个模块

    模块地图看责任边界

    `verify`、`route`、`checkpoint` 这类用户能感知的能力，适合成为模块。 它们有自己的职责、路径、文档和验证方式。

    支撑文件看归属关系

    `src/errors.ts` 负责统一 CLI 错误，`src/version.ts` 服务 `version` 命令。 它们更像 `cli` 模块的小零件，不是新的产品能力。

    更严谨的维护方式不是新增 `errors` / `version` 两个模块，而是在 .context/modules/cli.md 的 Code Paths 里把它们补为支撑路径。
