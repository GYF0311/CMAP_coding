3. 第一性目标复盘
cmap 的第一性目标不是“生成更多文档”，而是解决 AI coding 的连续性损耗：新会话、上下文压缩、项目变大、模块漂移后，AI 会重复阅读、重复猜测、重新建立项目模型。附件把目标拆成六点：减少盲扫、降低接续成本、稳定读取模块边界/职责/路径/关系、允许 AI 维护但不能污染长期事实、提供 Obsidian/HTML 阅读层、让 route / brief / checkpoint / finish / update / verify 成闭环。


从第一性原理看，AI coding 的上下文成本来自四类浪费：

定位成本：AI 不知道该先读哪些文件。

解释成本：AI 读到代码但不知道模块职责、边界和历史决策。

续接成本：AI 不知道上次做了什么、下一步是什么、什么已验证。

漂移成本：项目改了，但公共记忆没有改，后续 AI 读到旧地图。

cmap 当前已经覆盖了前 3 类的大部分：.context 作为 canonical source、modules/*.md 作为模块地图、CHECKPOINT.md 作为续接状态、VERIFY.md 作为验证入口、route/brief 作为开工包。附件里也说明，当前已有 19 个模块文档，覆盖 cli、context、verify、host、route、brief、benchmark、handoff、finish、update-agent、obsidian-adapter、reconcile-adapter 等。


但第 4 类“漂移成本”仍未真正解决。只要模块职责、路径归属、关系、验证方式、外部 adapter 状态发生变化，而 AI 或人没有把它们提升进可信层，地图就会老化。所以 cmap 的下一阶段核心不是增加更多手写文档，而是增加 evidence-backed generated facts。

7. hooks 设计方案
Claude Code 官方 hooks 已经覆盖 SessionStart、PreToolUse、PostToolUse、Stop、SessionEnd 等生命周期点，并支持 command/http/MCP/prompt/agent hook；其中 SessionStart stdout 可注入上下文，PreToolUse 可阻断工具调用。

cmap 的 hooks 设计应遵守一条总原则：

hooks 可以自动观察、记录、打包、生成候选、写 routine/generated evidence；
hooks 不可以直接修改 high-risk canonical semantic facts。
7.1 hook 权限矩阵
Hook	默认模式	可写位置	不可写位置	作用
SessionStart	assist	.context/out/session-brief.md	semantic canonical	输出 status/checkpoint/pending inbox/verify reminder
UserPromptSubmit	assist	.context/out/route-current.md	semantic canonical	根据用户 prompt 自动 route/brief 注入上下文
PreToolUse	strict guard	logs only	禁止直接写 MAP/DECISIONS/modules semantic sections	拦截危险 .context 直写、危险 shell
PostToolUse	observe	.context/logs/session-events.jsonl, .context/stats/*.json	semantic canonical	记录 Read/Edit/Write/Bash/verify evidence

三种模式：

  只写 logs/stats，不注入 context，不阻断。

9. route / graph / context packing 方案
9.1 是否引入语义搜索或代码图？
结论：要引入代码图，但不要一开始引入 embeddings。

aider 的 repo map 证明：对 AI coding 来说，符号级 repo map 非常有效，因为它把“整个 repo”压缩成关键文件、关键 class/function/signature，而不是让模型盲读。aider 文档明确说明其 repo map 包含全仓文件和关键符号定义，并用 Tree-sitter 提取 definitions/references。

Serena 证明了另一个方向：LSP-backed symbol retrieval 可以让 agent 在大代码库里按 symbol/reference/diagnostics 导航，而不是读整文件或 grep。

Repomix 则证明 context packing 需要格式、token count、ignore、安全扫描和 compression。

所以 cmap 的最小路线是：

v0.2: deterministic path/module graph
v0.3: hook-driven heat/activity graph
v0.4: import/test/package/symbol graph
v0.5: optional semantic adapter

13. 是否建议继续当前方向？
建议继续，而且应坚持当前核心定位：小而强的 repo-local project memory map CLI。

最终判断：

当前目标未完全达成；
当前方向正确；
当前 P0 安全但维护不足；
下一阶段必须做 hooks + generated evidence + graph-aware route + stale verify；
只要 v0.2-v0.4 落地，cmap 有机会成为真正可用、可推广的 AI coding 项目地图 CLI。✅

What is model context protocol (MCP)?
2025年10月28日 — Model Context Protocol (MCP), introduced by Anthropic in November 2024, is an open-source AI standard that enables large language models (LLMs) to interact securely with external databases, tools, and applications in real time. Traditionally, such integrations required custom, manual implementations, but MCP provides a client-server architecture to streamline these connections. The MCP host, typically an AI application or integrated development environment (IDE), contains the LLM, while the embedded MCP client translates user input into standard requests. These are sent to MCP servers—external tools or databases—that return the relevant data to the LLM via the client. By solving the N x M problem—where M tools must be integrated with N models—MCP reduces the need for custom integrations, cutting development costs and enabling scalable, modular systems in environments using microservices and cloud-native architectures. It supports use cases such as cloud management, software development, personalized AI assistants, and multi-agent orchestration. However, MCP carries security risks, including the potential for prompt injection attacks and management flaws from misconfigured servers. Since the protocol lacks built-in enterprise-level authentication, it depends on trust, making it vulnerable to threats like MCP-UPD (Unintended Privacy Disclosure). Despite these risks, MCP is gaining traction across the AI ecosystem due to its interoperability and efficiency.

The 4 most critical aspects of model context protocol (MCP) for developers building AI-native architectures
2025年9月23日 — This article from TechRadarPro explores the evolving role of the Model Context Protocol (MCP) in developing AI-native and composable enterprise software architectures. MCP is positioned as a crucial standard for integrating AI systems with tools, APIs, and data sources, addressing challenges like integration complexity, governance, and scalability. The article outlines four core aspects of MCP: 1. **Standardization of AI Integration**: MCP unifies how AI models interact with diverse services and tools, reducing the burden of custom code and increasing portability and auditability. 2. **Composable Architecture**: MCP enables modular, reusable AI systems that can collaborate autonomously and integrate seamlessly with APIs and services. 3. **Governance and Security**: Built-in observability, access control, and audit logging ensure secure and compliant AI operations across systems. 4. **Future-Proof Tooling**: MCP supports dynamic tool discovery and runtime skill expansion for AI agents, promoting flexibility and interoperability across frameworks. The article encourages developers to understand MCP, as it represents a transformative protocol for embedding AI into enterprise infrastructure with greater modularity, control, and future readiness.
