## P0-PR1：View flags + Overview/Verify 完整化

### 目标

修正 `cmap view export` 的数据收集与展示，让 HTML view 真正成为“项目地图审阅台”，而不是只显示模块列表。

### 当前问题

CLI 暴露了：

```bash
cmap view export --include-generated
cmap view export --include-inbox
cmap view export --include-freshness
```

但 `runViewExport()` 里调用的是：

```ts
const data = await collectViewData(cwd);
```

没有把 include flags 传进去。

同时当前 `CmapViewData` 只有 project、summary、modules、evidence、candidates、relationCandidates、warnings，没有结构化的 checkpoint/status/verify 信息。

### 修改范围

```text
src/commands/view.ts
src/view/collect.ts
src/view/schema.ts
src/view/render.ts
tests/integration/m19-view-export.test.ts 或新增 m21-view-hardening.test.ts
.context/modules/view.md
README.md
```

### 具体改动

#### 1. 让 include flags 真正生效

新增：

```ts
type CollectViewOptions = {
  includeGenerated?: boolean;
  includeInbox?: boolean;
  includeFreshness?: boolean;
};
```

调用改为：

```ts
const data = await collectViewData(cwd, {
  includeGenerated: Boolean(options.includeGenerated),
  includeInbox: Boolean(options.includeInbox),
  includeFreshness: Boolean(options.includeFreshness)
});
```

默认展示：

```text
Overview
Modules
Relations
Verify summary
Warnings
```

只有打开 flags 才展示：

```text
Generated Evidence
Inbox Candidates
Freshness
Relation Candidates
```

#### 2. 补 overview 数据

`CmapViewData` 增加：

```ts
overview: {
  purpose?: string;
  activeGoal?: string;
  currentTask?: string;
  nextStep?: string;
  verified?: string;
  lastVerified?: string;
};
```

数据来源：

```text
.context/MAP.md       -> Purpose
.context/STATUS.md    -> Active Goal / Next Steps / Last Verified
.context/CHECKPOINT.md -> Current Task / Next Step / Verified
```

#### 3. 补 verify 数据

`CmapViewData` 增加：

```ts
verify: {
  requiredCommands: Array<{
    purpose: string;
    command: string;
    expected?: string;
    when?: string;
  }>;
  manualChecks: string[];
};
```

数据来源：

```text
.context/VERIFY.md 的 Required Commands 表格
.context/VERIFY.md 的 Manual Verification
```

#### 4. 渲染层新增区块

HTML 页面新增：

```text
Overview
Verification
Canonical Relations
```

而不是只有 Modules / Evidence / Candidates。

### 验收标准

```bash
pnpm test tests/integration/m19-view-export.test.ts
pnpm dev view export --out _cmap-view
pnpm dev view export --include-generated --include-inbox --include-freshness --out _cmap-view
pnpm dev view export --check --out _cmap-view
```

必须满足：

```text
- 不传 include flags 时不展示 generated/inbox/freshness 详情。
- 传 include flags 时展示对应区块。
- HTML 里有 Active Goal / Current Task / Next Step。
- HTML 里有 VERIFY Required Commands。
- 数据源缺失时显示 Not available，不报错。
```

## P0-PR2：View check 强化

### 目标

让 `view export --check` 不只检测 embedded JSON，还能检测 HTML 模板变化。

### 当前问题

`viewDataMatches()` 只比较 `<script id="cmap-view-data">` 里的 JSON，忽略 `generatedAt`。如果修改 HTML/CSS/布局，但 data 不变，`--check` 仍可能 pass。

### 修改范围

```text
src/view/check.ts
src/commands/view.ts
src/view/render.ts
tests/integration/m19-view-export.test.ts
```

### 方案

二选一：

#### 推荐方案 A：normalized HTML comparison

`--check` 时：

```text
currentHtml = read existing file
expectedHtml = renderViewHtml(newData)
normalize(currentHtml) == normalize(expectedHtml)
```

normalize 规则：

```text
- 去掉 generatedAt
- 去掉 sourceCommit 如果你认为它 volatile
- 规范化空白
```

#### 简化方案 B：rendererVersion

`CmapViewData` 增加：

```ts
rendererVersion: "cmap.view_renderer.v1"
```

模板变化时升级版本。

我建议做 **方案 A**，更稳。

### 验收标准

```text
1. 刚 export 后 --check pass。
2. 手动改 HTML title 后 --check fail。
3. 只改 generatedAt 不 fail。
```

## P0-PR3：RelationPatch + MapPatch 路径安全与证据校验

### 目标

补齐 path safety 和 evidence/module 校验，避免候选和 generated evidence 写入脏数据。

### 当前问题 A：RelationPatch 路径没有统一 safe path

`readRelationPatch()` 用 `path.resolve(cwd, from)`；`validateOperation()` 用 `path.join(cwd, evidence)` 检查 evidence。没有统一使用 `resolveInsideRoot()`。

### 当前问题 B：MapPatch evidence.append 校验不够完整

`evidence.append` 会读取 `fields.module`、`fields.files`，但当前主要校验的是 `operation.evidence` 中的文件。如果 AI 把文件只放在 `fields.files`，可能不会被逐个验证。同时没有强校验 moduleId 是否存在。

### 修改范围

```text
src/core/relation-patch.ts
src/core/map-patch.ts
tests/integration/m20-relation-candidates.test.ts
tests/integration/m7-update-agent.test.ts
```

### 具体改动

#### RelationPatch

改为：

```ts
const target = await resolveInsideRoot(cwd, from);
```

evidence 校验：

```ts
const evidencePath = await resolveInsideRoot(cwd, evidence);
if (!(await fileExists(evidencePath))) reject;
```

禁止：

```text
absolute path
../ escape
```

#### MapPatch evidence.append

新增：

```ts
const modules = await loadModuleIndex(cwd);
if (!modules.some(m => m.id === moduleId)) {
  return inbox/reject reason: unknown module
}
```

对 `fields.files`：

```ts
for each file in fields.files:
  resolveInsideRoot(cwd, file)
  fileExists
```

`verification.evidence` 允许 command-only，但如果提供 files，也必须校验。

### 验收标准

```text
- relate ingest --from ../outside.json 报错。
- RelationPatch evidence: "../x" 被 reject。
- MapPatch evidence.append unknown module 进入 inbox/reject。
- MapPatch evidence.append fields.files missing file 进入 inbox。
- verification.evidence command-only 可以 apply。
```

## P0-PR4：Freshness v2 精准化

### 目标

让 `verify --freshness` 更符合语义审阅，而不是“看起来有 index 就 checked”。

### 当前问题

`freshnessWarnings()` 在没有 snapshot 时会 build 当前 index，不一定产生 warning；`verify --freshness` 仍输出 checked。semanticHash 只 hash `module.body`，没包含 frontmatter 里的 aliases/paths/relations。pending candidates 只扫描 `.context/inbox` 顶层，不扫描 `.context/inbox/relations`。

### 修改范围

```text

tests/integration/m18-freshness-inbox-promote.test.ts
```

### 具体改动

#### 1. missing snapshot warning

如果 `.context/generated/freshness.json` 不存在：

```text
Freshness: no snapshot found; run cmap freshness snapshot
```

exit code 仍可为 0，但必须 warning。

#### 2. semanticHash 包含 frontmatter semantic fields

hash 内容改为：

```ts
{
  body: module.body,
  aliases: module.aliases,
  pathsInclude: module.pathsInclude,
  pathsExclude: module.pathsExclude,
  relations: module.relations,
  status: module.status,
  layer: module.layer,
  risk: module.risk
}
```

#### 3. 扫描 relation candidates 子目录

pending candidates 数据源增加：

```text
.context/inbox/*.md
.context/inbox/relations/*.md
.context/inbox/relations/*.json
```

#### 4. 区分 high-risk / routine

warning 文案区分：

```text
Freshness: high-risk candidate pending
Freshness: routine candidate pending
Freshness: relation candidate pending
```

### 验收标准

```bash

pnpm dev verify --freshness
```

必须覆盖：

```text
- 没 snapshot 时 warning。

- relation candidate 子目录能被 freshness 识别。
- high-risk candidate 文案明确。
```

## P1-PR1：统一 Candidate Store

### 目标

解决 MapPatch / reconcile / obsidian pull / relate / inbox promote 之间 candidate 格式不统一的问题。

### 当前问题

`relate` 已经写：

```text
.context/inbox/relations/*.json|md
```

但 MapPatch 写的是一个聚合 Markdown inbox report，`inbox promote --apply` 主要消费顶层 `.context/inbox/*.md` frontmatter。

这会导致：

```text
AI 提了 module.alias.add
update --agent 写到 inbox report
但 inbox promote --apply 不一定能直接消费它
```

### 新结构

```text
.context/inbox/candidates/
  candidate-<timestamp>-<hash>.json
  candidate-<timestamp>-<hash>.md

.context/inbox/relations/
  relation-<timestamp>-<hash>.json
  relation-<timestamp>-<hash>.md
```

### Candidate schema

```ts
type CmapCandidate = {
  schema: "cmap.candidate.v1";
  id: string;
  fingerprint: string;
  createdAt: string;
  source: "mappatch" | "relate" | "reconcile" | "obsidian-pull" | "manual";
  type:
    | "module.alias.add"
    | "module.path.add"
    | "evidence.merge"
    | "verification.evidence"
    | "module.semantic.update"
    | "decision.record"
    | "verify.policy.update";
  target: string;
  risk: "routine" | "medium" | "high";
  confidence: number;
  summary: string;
  evidence: string[];
  fields: Record<string, unknown>;
  canonical: false;
};
```

### 命令调整

```bash
cmap inbox status
cmap inbox triage
cmap inbox promote <id> --dry-run
cmap inbox promote <id> --apply
```

统一读取：

```text
.context/inbox/*.md legacy
.context/inbox/candidates/*.json
.context/inbox/relations/*.json
```

### 验收标准

```text
- MapPatch module.alias.add 写 candidate JSON+MD。
- inbox promote --apply 能直接 apply 该 candidate。
- duplicate fingerprint 会 skip。
- legacy markdown inbox 仍可读，但 warning 为 legacy。
```
